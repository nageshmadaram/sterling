# Adaptive Edge V2 — Canonical Research Dataset Ingestion and Provenance Contract

**Artifact:** A69  
**Status:** SPECIFICATION  
**Version:** 2.1.0

## 1. Purpose

A69 defines the immutable boundary between provider data and the versioned research dataset.

## 2. Input authority

```text
TrueData only
```

Kite data is not permitted as a substitute input to the research dataset.

Kite data belongs to execution, position and accounting evidence.

## 3. Ingestion stages

```text
TrueData source
    -> raw capture
    -> source validation
    -> canonical event normalization
    -> deterministic ordering/preservation
    -> dataset partitioning
    -> manifest
    -> content hash
    -> research dataset
```

The raw source must be retained whenever the entitlement and provider terms permit it.

## 4. No silent transformation

Ingestion may normalize representation, but must not silently:

- fill missing observations;
- interpolate prices;
- infer trades from quotes;
- infer quote quantities from trades;
- replace missing TrueData values with Kite values;
- discard source events solely because they are inconvenient for the model;
- alter timestamps without preserving the provider timestamp.

Any transformation must be deterministic and versioned.

## 5. Dataset identity

Every dataset version must have a content-addressable identity:

```text
source
provider_contract_version
instrument_universe
requested_interval
actual_coverage
source_timezone
raw_content_hash
canonicalization_version
schema_version
```

The manifest must record at least:

```text
dataset_version
created_at
provider
provider_contract_version
instrument_id / universe_version
source_resolution
requested_start
requested_end
actual_start
actual_end
row/event count
source timezone
canonical timezone
schema version
canonicalization version
feature-set version
label-definition version
research-config version
content hash
validation result
```

## 6. Partitioning

The dataset must be partitioned chronologically before model fitting.

The partition mechanism must preserve event ordering and must be compatible with the walk-forward purge/embargo contract.

No random shuffle may be used to construct train/validation/holdout populations for time-dependent market data.

## 7. Availability boundary

Each canonical event must preserve:

```text
event_time
availability_time
ingestion_time
```

When the provider does not expose an authoritative availability timestamp, the field remains UNKNOWN and the research engine must use the declared conservative availability policy.

The policy must not assume that an event was observable merely because its event timestamp precedes the decision timestamp.

## 8. Raw versus derived data

```text
RAW
    provider observations preserved as received

CANONICAL
    deterministic representation with explicit schema

DERIVED
    bars/features generated by versioned deterministic transforms
```

Derived artifacts must retain a reference to the source dataset version.

## 9. Data quality

A dataset is rejected when any mandatory integrity condition fails:

```text
missing mandatory schema
invalid instrument identity
duplicate canonical event identity
non-deterministic ordering
unresolved timestamp timezone
impossible numeric values
unexplained source gaps affecting required research windows
hash mismatch
manifest mismatch
```

A gap that is genuinely present in the provider source remains a gap. It is not repaired merely to satisfy downstream algorithms.

## 10. Reproducibility

Given:

```text
same raw source
same source contract version
same canonicalization version
same schema version
same configuration
```

the canonical dataset must be byte-for-byte reproducible.

If reproducibility changes, the dataset version must change.

## 11. Dataset lineage

Every downstream artifact must be traceable through:

```text
provider source
    -> dataset version
    -> canonical event ID
    -> feature snapshot ID
    -> prediction ID
    -> decision ID
    -> authorization ID
    -> Kite order ID
    -> Kite trade ID
    -> position state
    -> outcome ID
    -> label ID
```

The research dataset does not contain execution outcomes merely because the same strategy later traded them.

## 12. TrueData retention constraint

TrueData documentation currently states default REST availability of:

```text
Tick data       -> last 5 trading days
Minute bars     -> last 6 months
Daily bars      -> 10+ years
```

Therefore a research request exceeding those defaults must explicitly identify an entitled source such as an applicable extended-history service, replay mechanism, or separately supplied historical dataset.

The system must not assume that the default REST endpoint can provide multi-year tick history.

## 13. Kite exclusion

The ingestion layer must have no dependency on Kite market quotes, orders, positions, or trades.

Kite becomes relevant only after an economic decision reaches the execution boundary.

## 14. Security

Credentials, API secrets, access tokens and private provider configuration must never be stored in:

```text
source control
dataset content
public manifests
logs
exception messages
```

## 15. Failure conditions

Ingestion fails closed when:

1. source authentication fails;
2. source entitlement is insufficient;
3. provider schema changes unexpectedly;
4. timestamp semantics are unresolved;
5. mandatory fields are absent;
6. canonicalization is non-deterministic;
7. content hash does not match the manifest;
8. the source cannot cover the declared research period;
9. the requested data would require an undocumented provider substitution.

## ARCHITECTURE STATUS

Frozen: TrueData-only research ingestion, immutable source preservation, provenance, deterministic canonicalization, content-addressed datasets, chronological partitioning, no silent repair.

## UNRESOLVED

Actual dataset coverage and historical tick entitlement for the user's TrueData account.

## BLOCKERS

The empirical research pipeline cannot be truthfully executed until a real, entitled TrueData dataset covering the declared research period is acquired and its manifest validated.
